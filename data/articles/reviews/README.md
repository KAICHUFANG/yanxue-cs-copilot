# 活动回顾推文存档

这里放**活动结束之后**的公众号回顾推文原文，一期一个文件。

```
review_第16期.md        ← 期次统一成阿拉伯数字，避免「第九期/第9期」存成两份
index.jsonl            ← 一行一条：何时存的、哪一期、多少字、首行
```

## 为什么单独存，不放进 activities.json

活动记录是**单活动**模型：一期办完，粘进新一期推文就整条替换掉，旧的只进 `archive/`。

但回顾推文是**那一期的历史资料**——客服两个月后还会被问「第十六期回顾里写了什么」。
跟着活动记录走的话，换一期就没了。所以它按期次单独存，只往后加。

## 怎么存

把回顾推文全文直接粘进对话框就行，不用说期次（期次从正文里认）。
存回顾推文**不会改动任何活动字段**——回顾里全是上一期的旧值，抽了就是串期。

## 它会用在哪

1. 「回顾分享」那条群文案的 `{{具体细节}}`（系统按它拟初稿）
2. `{{回顾推文链接}}`（原文里带了链接就自动提取）
3. 客服点到期次提问时，那一期原文会被附进上下文
