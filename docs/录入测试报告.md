## 三、修复的两个真问题

### ① 粘贴别期推文会把当期整条覆盖（严重）

**现象**：客服在改第十六期，顺手把第十七期的推文粘进来，模型抽出
`session_label=第十七期`、`date=2026-11-07`、`title=海岛珊瑚守护者`……
代码原样写入，**S16 整条记录被换成了第十七期的内容**。

```
session_label   第十六期          → 第十七期   ← 被覆盖
title           自贸港小商人…      → 海岛珊瑚守护者 ← 被覆盖
date            2026-10-24       → 2026-11-07  ← 被覆盖
capacity        25               → 30          ← 被覆盖
```

**根因**：模型抽得没错（它照实抽了），错在**代码没有纪律检查**。

**修法**：加 `_cross_session_guard()`。抽到的期次和当前期次不一致 → 一律不写。
这是纪律问题不是语义问题，所以由代码判定，而且判定方式很简单：比数字。

```
客服：粘第十七期推文（当前在改 S16）
系统：🛑 这段内容写的是第17期，但当前正在编辑的是第16期，已拒绝写入
磁盘：没有变化 ✅
```

顺带修了一个坑：模型抽出来的 `session_label` 是「**第十七期**」这种中文数字，
最初护栏只抓阿拉伯数字，导致**护栏形同虚设**（第一次测试就是这样漏过去的）。
现在中文数字也认。

### ② 每条回复都在罗列缺项（干扰）

**现象**：几乎每条回复都带一句「其余集合地点、集合时间、是否分组、每组人数尚未填写」。

**根因**：生成确认语时，我把缺项清单喂给了模型，它就照抄一遍。

**修法**：不喂清单，明确要求「不要罗列还缺哪些字段，界面右侧有实时面板」。
现在回复长度：

| 场景 | 修前 | 修后 |
|---|---|---|
| 录入室外 | 60+ 字（含 4 项缺项清单） | 17 字：「已成功录入：室内外类型为"室外"。」 |
| 自我更正 | 60+ 字 | 11 字：「已按"室内"成功录入。」 |

## 四、现在这套录入是怎么分工的

```
客服打一句话
     ↓
① classify_input()          ← 模型判断：这是补充信息，还是在提问？
     ↓ update                    ↓ question
② 代码校验字段白名单            把这一期资料给模型，直接回答
③ 代码查期次是否跨期（护栏）
     ↓ 通过
④ store.update_activity()   ← 字段校验 + 写前备份
     ↓
⑤ 模型说一句确认（不罗列缺项）
     ↓
右侧状态面板由 store.missing_fields() 重算并刷新
```

**没有一行关键词表。** 判断归模型，纪律归代码。

| **不能新建期次** | 上面第 17 条那样粘新推文，现在只能被拦下，没法真的建成第十七期。这是 `create_activity` 该干的事 |

| 跨期护栏只看 session_label | 如果推文里根本没写第几期，护栏识别不出来 |
| 长推文会一次改 15 个字段 | 一旦抽错，改动面很大。目前靠写前备份 + 面板可见兜底 |
